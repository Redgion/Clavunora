# Clavunora: тестовая настольная сборка

Текущая локальная проверка: **0.4.0rc3, Linux/Fedora 44** — новый интерфейс, достижения и обе темы. Этот локальный архив собран на Fedora 44 (glibc 2.43), для других дистрибутивов совместимость не подтверждена. Windows/Android в этой итерации не собираются.

Распакуйте архив целиком. Linux: запустите `Clavunora/Clavunora`; Windows: `Clavunora/Clavunora.exe`. Python отдельно не нужен. Папка `_internal` необходима. Это предварительная сборка, не подписанный установщик.

Настройки и библиотека сохраняются отдельно: Linux — `$XDG_CONFIG_HOME/PianoFlow` или `~/.config/PianoFlow`; Windows — `%APPDATA%/PianoFlow`. Перед переносом между компьютерами используйте архив библиотеки в настройках приложения.

Библиотека распространяемой версии содержит 98 доступных произведений. № 48 и № 76
временно исключены из распространяемых файлов, но их названия сохранены в плане.
Материалы CC BY-NC-SA 4.0 предназначены только для некоммерческого использования.
Не все партитуры имеют разметку рук и пальцев; педагогическая проверка продолжается.

Linux: откройте `.rpm` (Fedora) или `.deb` (Ubuntu 24.04+) в системном установщике пакетов. Для переносимого архива запустите `sh install.sh` из распакованной папки — без sudo, с ярлыком в меню.
Windows: установщик `*-setup.exe` устанавливает приложение в личную папку; ZIP
остаётся переносимой альтернативой. Удаление приложения не удаляет результаты.

Материалы Mutopia, Noctave, PDMX, Piano: Soloist и Wikimedia сопровождаются исходниками, авторством и условиями в `_internal/pianoflow/resources/catalog`. Конвертированные партитуры под CC BY-SA сохраняют лицензию источника. Qt/PySide6 динамически подключаются; лицензии зависимостей находятся в `licenses`. SoundFont/FluidSynth не включены: этот дополнительный движок настраивается отдельно. Обычный предпросмотр не требует SoundFont.

Linux-сборка, созданная на Fedora, предназначена прежде всего для совместимой системы. Для более широкого распространения собирайте на старейшей поддерживаемой Linux-системе (релизный CI: Ubuntu 24.04; glibc 2.39+) и проверяйте на целевых дистрибутивах. Linux и Windows собираются на своих ОС; эта конфигурация не выполняет кросс-компиляцию.

Разработчику:

```sh
python -m pip install '.[desktop,dev,build]'
python scripts/build_desktop.py
```

Сценарий проверяет тесты, собирает приложение, запускает самопроверку упакованного приложения в отдельной временной папке и только затем создаёт архив. `--skip-tests` пропускает только pytest, но не самопроверку. Workflow `.github/workflows/desktop.yml` подготавливает архивы Linux/Windows без публикации и подписи. Локальная успешная сборка Linux не подтверждает Windows-проверку.

Сборка и ограничения предварительной версии Android описаны в ANDROID.md.
