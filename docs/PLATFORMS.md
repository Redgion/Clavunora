# Целевые платформы PianoFlow

Статус: требование продукта, зафиксировано 24 октября 2026 по запросу владельца проекта.

PianoFlow планируется выпускать для **Android, iOS, iPadOS, Windows, Linux и macOS**.
Android включает телефоны и планшеты; устройства Apple — iPhone и iPad.
Это требование к развитию архитектуры и выпуску, а не заявление о готовых сборках.

## Матрица выпуска

| Платформа | Устройства | Текущее состояние |
|---|---|---|
| Linux | Компьютеры, приоритет Fedora KDE | Есть запускаемая версия; автоматические тесты и offscreen-рендер. Физический MIDI/звук требуют отдельной проверки. |
| Windows | Компьютеры | Запланировано; сборки и аппаратные тесты не выполнены. |
| macOS | Mac | Запланировано; сборки и аппаратные тесты не выполнены. |
| Android | Телефоны и планшеты | Запланировано; необходим мобильный интерфейс, MIDI-интеграция и проверка сборки. |
| iOS | iPhone | Запланировано; необходимы мобильный интерфейс, MIDI-интеграция и сборка на macOS/Xcode. |
| iPadOS | iPad | Запланировано; необходимы планшетный интерфейс, MIDI-интеграция и сборка на macOS/Xcode. |

Минимальные версии ОС, поддерживаемые архитектуры и список проверенных устройств
будут определены по результатам сборок и аппаратных испытаний.

## Общие требования

- Нативное устанавливаемое приложение; работа основных режимов без интернета.
- Общие модели композиции, музыкального времени, проверки нот и статистики.
- Одинаковая музыкальная логика на телефонах, планшетах и компьютерах.
- Адаптация экранов к устройству: компактная навигация на телефоне, больше пространства
  для клавиатуры и нот на планшете; поддержка доступных ориентаций без потери сеанса.
- Сенсорный ввод нескольких нот одновременно, включая корректное отпускание пальцев.
- USB-MIDI и BLE-MIDI там, где их поддерживают ОС, инструмент и подключение.
  Проверка возможностей устройства и понятное сообщение при недоступности транспорта.
- Корректные разрешения, системный выбор файлов, локальные данные в каталоге приложения,
  прерывания аудио, уход в фон и возвращение. Фоновая игра не обещается по умолчанию.
- Единая схема локальных данных с миграциями; облачная синхронизация — отдельная будущая функция.
- Готовая сборка каждой платформы проверяется на реальном устройстве перед объявлением поддержки.

## Архитектурное направление

Текущая версия остаётся рабочей Linux-основой на Python/PySide6. Музыкальные модели
`core/song.py`, `core/state.py`, `core/transport.py` уже не зависят от виджетов Qt.
Это основа для переиспользования, но не доказательство переносимости всего приложения.

Нужно постепенно вынести проверку исполнения из `ui/lesson.py` в независимый
модуль обучения. Представление, MIDI, аудио, настройки/файлы и жизненный цикл
приложения должны подключаться через отдельные платформенные адаптеры.
Текущие mido/python-rtmidi, QAudioSink и пути настроек нельзя автоматически считать
готовыми мобильными адаптерами. Общий код должен работать с нормализованными
MIDI-событиями и не знать об ALSA, Android MidiManager или Apple Core MIDI.

Первый кандидат для общего сенсорного интерфейса — Qt Quick/QML с независимой
музыкальной логикой. Это направление для технического прототипа, а не уже
согласованная полная перепись. Текущий QWidget-интерфейс с минимумом 1000×700
не является телефонным интерфейсом. Мобильную переносимость Python-зависимостей,
нативные мосты MIDI, сборку и производительность нужно подтвердить до миграции.
Если прототип выявит блокирующие ограничения, выбор стека пересматривается
с владельцем проекта до замены рабочей реализации.

## Проверенные направления инструментария

В Qt for Python документированы инструменты развёртывания для desktop, Android и iOS.
Их наличие само по себе не гарантирует переносимость нашего приложения и зависимостей.

- [Desktop deployment](https://doc.qt.io/qtforpython-6/deployment/index.html): Windows, Linux, macOS.
- [Android deployment](https://doc.qt.io/qtforpython-6/deployment/deployment-pyside6-android-deploy.html):
  отдельная сборочная среда, Android SDK/NDK и платформенные wheels; APK/AAB.
- [iOS deployment](https://doc.qt.io/qtforpython-6/deployment/deployment-pyside6-ios-deploy.html):
  генерация проекта Xcode на macOS, платформенные wheels, сборка и подпись средствами Apple.
- [Android MIDI](https://developer.android.com/reference/android/media/midi/MidiManager):
  системный MidiManager и проверка наличия MIDI-возможностей устройства.
- [Apple Core MIDI](https://developer.apple.com/documentation/coremidi):
  платформенный MIDI API, включая BLE-MIDI.

Версии SDK, Qt/PySide6 и требования магазинов проверяются заново при подготовке сборки.
Текущие зависимости проекта не объявляются совместимыми с мобильными платформами
только на основании документации новых версий Qt.

## Порядок работ

1. Сохранить работающую Linux-версию и вынести обучение из UI в общее ядро.
2. Сделать небольшие проверочные сборки Android и iOS: запуск, падающие ноты,
   multitouch, звук, импорт файла и реальный MIDI. Для iOS потребуется Mac с Xcode.
   Выполнить этот шаг до масштабной доработки интерфейса, чтобы проверить выбор стека.
3. По результатам выбрать способ общего интерфейса и адаптеров; определить минимальные ОС.
4. Подготовить воспроизводимые desktop-сборки и проверки Linux/Windows/macOS.
5. Адаптировать интерфейс и MIDI для Android-телефонов/планшетов, затем iPhone/iPad;
   конкретную очередность мобильных релизов можно изменить по результатам проверок.
6. Подготовить подпись, установщики/пакеты и тестовые выпуски. Публикация в магазинах
   и создание аккаунтов разработчика требуют отдельного решения владельца.

## Критерий готовности каждой платформы

Установка на целевое устройство, запуск без среды разработки, открытие мелодии,
плавные ноты и управление временем, работа доступного MIDI-транспорта и педали,
сенсорный/аппаратный ввод, проверка исполнения, сохранение данных после перезапуска,
корректное восстановление после отключения инструмента/прерывания аудио.
Для телефона/планшета дополнительно проверяются multitouch, ориентация и уход в фон.
