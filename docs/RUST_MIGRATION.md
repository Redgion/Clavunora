# Clavunora: начало переноса на Rust

Текущий кандидат desktop-выпуска — Rust 1.0.0-rc.1. Python 0.4.0rc3 сохраняется как прежняя реализация; запись/экспорт по-прежнему отложены. Подготовка Linux, Windows и macOS описана в DESKTOP_RELEASE.md.

## Уже перенесено

- Отдельное ядро `clavunora-core`, не зависящее от окон и графического движка.
- Совместимый JSON-формат нот: руки, пальцы, дорожки, MIDI-каналы, темп и его изменения, метаданные и источники.
- Существующие 97 нотных файлов каталога плюс 24 урока и три учебных варианта: 124 записи, из них 98 произведений согласованной сотни. № 48 и № 76 остаются исключены из поставки.
- 24 урока курса и три варианта «С днём рождения»; первые шесть уроков и варианты сохраняют исходный контракт Python.
- Состояние клавиш и Sustain с изоляцией источников/каналов, Note On velocity=0, CC64/120/121/123.
- Музыкальные часы: монотонное время, подготовка, пауза, перемотка ядра и скорость 25–200%.
- Ожидание аккорда: все клавиши вместе и новые нажатия для повторяющихся нот.
- SQLite schema v1: пьесы, избранное, история, сохранение новых результатов и всех шести наград. Пользовательские редакции и удалённые встроенные пьесы сохраняются.
- Нативный Linux-интерфейс egui/eframe с восемью разделами, переключением темы, каталогом, проверочной клавиатурой и простым отображением движущихся нот.
- MIDI-ввод через midir/ALSA: выбор порта, обнаружение потери связи и восстановление соединения с остановкой занятия. Аппаратную проверку выполняет пользователь.

Программный звук работает: встроенный инструмент без загрузок и необязательный локальный SoundFont через системный FluidSynth. Экранная клавиатура настраивается от 13 до 88 клавиш; компьютерные клавиши соответствуют C4–C5, внешний MIDI-инструмент может посылать ноты полного диапазона. Экран занятия сохраняет базовое отображение падающих нот; его учебные инструменты ещё предстоит расширить.

## Данные

По умолчанию Rust использует **`~/.config/ClavunoraRustPreview/library.sqlite3`**, с учётом `XDG_CONFIG_HOME`. Рабочая папка Python `~/.config/PianoFlow` защищена от случайного выбора через `--data-dir`.

Импорт доступен только явной командой:

```sh
./scripts/run-rust.sh --data-dir ./build/my-rust-copy \
  --import-legacy "$HOME/.config/PianoFlow/library.sqlite3"
```

Это согласованный снимок средствами SQLite backup; исходная база открывается только для чтения. Существующий файл назначения не перезаписывается. Ноты проверяются, неподдерживаемая версия схемы отвергается. Попытки, награды, предпочтения и бинарные MIDI-записи копируются вместе с базой. После импорта запускать без `--import-legacy`. Проверка копии без окна:

```sh
./scripts/run-rust.sh --data-dir ./build/my-rust-copy --inspect
```

Изменения в Rust-копии не синхронизируются обратно в Python. Настройка темы сохраняется в Rust-копии отдельно от темы Python. JSON-файл настроек устройства Python пока не импортируется.

## Что ещё не перенесено

Издательская нотная вёрстка с исходными тональностями, паузами и голосами, поддержка специальных сценариев коротких MIDI-клавиатур и установщик. Запись/экспорт отложены пользователем. MIDI/MusicXML, редактор разметки, фрагменты/повторы и собственный формат резервных копий уже доступны. Итоговая точность считает найденные ноты/группы; ошибки ритма и удержания показываются отдельно. В ожидании ритм и длительность удержания не оцениваются.

Согласованный дизайн реализован в 0.4.0; остаётся пользовательская проверка. Запись и экспорт сейчас не переносить. Поддержка компактных MIDI-клавиатур записана в [план](RUST_NEXT_STEPS.md); специальные сценарии для короткого диапазона пока не реализованы.

## Разработка на Linux

Рабочее пространство: `rust/Cargo.toml`; версии зависимостей зафиксированы в `rust/Cargo.lock`. Проверено с Rust 1.99.1. Локальный компилятор этого рабочего места лежит в игнорируемой папке `build/rust-toolchain`; `scripts/cargo-rust.sh` выбирает его, если он есть, иначе использует системный Cargo. Скрипт не устанавливает компилятор автоматически. Артефакты Cargo — `build/rust-target`.

```sh
./scripts/cargo-rust.sh test --locked --workspace
./scripts/cargo-rust.sh clippy --locked --workspace --all-targets -- -D warnings
./scripts/cargo-rust.sh build --locked -p clavunora-rust
.venv/bin/python scripts/check_rust_compat.py
./scripts/run-rust.sh
```

Самопроверка готового бинарного файла, без дисплея и пользовательских данных:

```sh
./build/rust-target/debug/clavunora-rust --self-test
```

Python нужен только для межъязыкового теста совместимости, не для работы Rust-приложения. Для сборки нужны C-компилятор, pkg-config и ALSA development files; при запуске — системные библиотеки ALSA и графики Wayland/X11/OpenGL.

Технические источники: [Rust/rustup](https://rust-lang.org/tools/install/), [eframe](https://docs.rs/eframe/0.34.3/eframe/), [midir](https://docs.rs/midir/0.11.1/midir/), [SQLite backup через rusqlite](https://docs.rs/rusqlite/0.41.0/rusqlite/backup/index.html).

## Результат первой итерации

- 17 Rust-тестов: музыкальное ядро, девять Python-партитур, база, удалённые произведения, тема, связь ввода с ожиданием и 16 отрисовок интерфейса (8 разделов × 2 темы).
- Строгая проверка Clippy без предупреждений и проверка rustfmt.
- Межъязыковой тест на работающей Python/SQLite WAL-базе: исходный файл и WAL неизменны, пользовательские редакции, удаления, избранное, попытки, награды и записи сохранены в копии; повторный импорт и выбор рабочей папки Python отвергаются.
- Оптимизированный Linux-файл проверен вне исходников после распаковки архива, без зависимости от Python. Проверено настоящее окно Wayland/OpenGL; неблокирующий обмен буферов предотвращает остановку событий при фоновом окне. Физическое пианино в Rust ещё не проверено.
- Локальный пакет: `dist/Clavunora-Rust-0.1.0-linux-x86_64.tar.gz`; исполняемый файл: `dist/Clavunora-Rust-preview/clavunora-rust`. Публикация не выполнялась.

## Вторая итерация · оценка и сохранение (0.2.0)

Перенесён `Performance`: ближайшее совпадение по ноте/времени, объединение унисонов, лишние/пропущенные ноты, ранние/поздние нажатия, короткое/долгое удержание и неотпущенные ноты. Допуски и задержка переводятся из реального времени в музыкальное с учётом скорости. 170 контрольных сценариев генерируются существующим Python-движком (`scripts/generate_rust_scoring_contract.py`) и проверяются в Rust. Дополнительно проверена партитура на 3000 нот.

MIDI-пакет получает монотонную отметку непосредственно в callback. Оценка использует время получения пакета, а не время последующей отрисовки. Пока не проверены физическое пианино и задержка конкретного MIDI-драйвера.

Пауза, уход со страницы, потеря фокуса, изменение режима/скорости/допуска завершают текущую попытку как незавершённую. Новая попытка сохраняет собственные настройки. В ожидании требуется пройти все группы; фрагменты и продолжение с середины не считаются целой пьесой. Пустая прерванная попытка без нот и ошибок не записывается. Прохождение отмечается для полной пьесы при точности от 90% без ошибок.

Каждый результат получает постоянный случайный ID. Повторное сохранение не создаёт дубль. Запись результата, отметка прохождения и первые две награды находятся в одной SQLite-транзакции. При ошибке результат остаётся в очереди с кнопкой повтора; обычное закрытие предупреждает о несохранённых данных. Принудительное завершение процесса/сбой питания не гарантирует сохранения очереди в памяти.

История показывает дату, режим, скорость, завершение и подробности ошибок. Формат отчётов и хеши версий партитур совместимы с Python; native-результат также проверяется чтением и ZIP-восстановлением на стороне Python. Старые награды и даты не перезаписываются. Rust пока начисляет только «Первые ноты» и «Первое произведение».

Пакет этой итерации: `dist/Clavunora-Rust-0.2.0-linux-x86_64.tar.gz`. Стабильная папка запуска — `dist/Clavunora-Rust-preview/clavunora-rust`; исполняемый файл заменяется атомарно, чтобы не обрывать уже открытую старую версию. Для проверки новой версии её нужно запустить заново.

Проверка второй итерации: 35 Rust-тестов, включая 170 контрольных сценариев Python; строгий Clippy без предупреждений; проверка хешей всех 106 партитур/упражнений. Дополнительно новый Rust-отчёт о ритме сравнивается с Python и проходит его ZIP-сохранение/восстановление. Встроенная самопроверка создаёт две попытки исключительно во временной базе и отрисовывает все восемь разделов в обеих темах, включая историю с ошибками.

## Третья итерация · звук и достижения (0.3.0)

Звук работает в отдельном потоке ALSA, независимо от отрисовки окна. Встроенный инструмент не требует дополнительных загрузок: учитывает высоту и силу нажатия, повторные ноты, аккорды и Sustain. Полный MIDI-диапазон; смешивание источников не обрывает общую ноту при отпускании одного из них. Есть громкость, отключение, сброс нот, выбор ALSA-выхода и переподключение после ошибки. Параметры сохраняются в Rust-профиле. Встроенный тембр — простой синтезированный инструмент, не семплированное акустическое пианино.

Для семплированного звука можно указать свой `.sf2`/`.sf3`; необходима системная `libfluidsynth.so.3`. В Linux-пакет библиотека FluidSynth и SoundFont не включены. При отсутствии зависимости/файла выводится ошибка и доступен возврат к встроенному инструменту. Временная библиотека из официального Fedora RPM использована только для проверки и не установлена в систему. API: [FluidSynth settings](https://www.fluidsynth.org/api/group__settings.html), [ALSA PCM](https://www.alsa-project.org/alsa-doc/alsa-lib/pcm.html).

Кнопка «Послушать пьесу» останавливает занятие и включает отдельное прослушивание с текущей скоростью. Звуки демонстрации не поступают в MIDI-состояние и оценку, не создают попытки и не открывают награды. Начало занятия или переход на другую страницу останавливает прослушивание. Независимый метроном в настройках: 30–240 ударов в минуту, 1–12 долей, акцент первой доли. Он не синхронизирован автоматически с темпом партитуры.

Начисляются все шесть наград, включая точность, обе руки, семь последовательных местных календарных дней и пять уровней сложности. Дата первого получения сохраняется. Счётчики вычисляются по истории с реальными верными нотами; молчание и прослушивание не дают прогресса. Фрагменты не дают наград за целую пьесу. Старые достижения импортированной копии сохраняются; история пересчитывается при открытии копии. Выдача новых наград находится в той же транзакции, что и запись результата. Для зачёта пяти уровней используется сложность сохранённого отчёта, даже если пьеса впоследствии удалена.

Проверка настоящего выхода короткой нотой и щелчком (без библиотеки, записи и экспорта):

```sh
./dist/Clavunora-Rust-preview/clavunora-rust --audio-test
# При установленном FluidSynth:
./dist/Clavunora-Rust-preview/clavunora-rust --audio-test --soundfont /path/to/piano.sf2
```

Пакет: `dist/Clavunora-Rust-0.3.0-linux-x86_64.tar.gz`. Внешний инструмент всё ещё требует ручной проверки. Интерфейс остаётся временным; новую визуальную концепцию обсуждаем следующим этапом.

Проверки 0.3.0: 44 Rust-теста, включая 170 сценариев оценки Python; Clippy без предупреждений; все шесть наград сравнены с Python на отдельной истории. Проверены реальный ALSA/PipeWire-выход встроенного инструмента и SoundFont, величина сформированного сигнала, настоящее окно и запуск самопроверки из распакованного архива. Физическая клавиатура пользователя в этом проходе не проверялась.

## Четвёртая итерация · Summer Aero (0.4.0)

Согласованный стеклянный дизайн реализован в Rust/egui. Летний пейзаж без снега встроен в бинарный файл; полупрозрачные панели используют размытый участок того же фона, градиент, светлую кромку и тень. Название Clavunora набрано встроенным шрифтом Liberation Serif. Источник изображения, окончательный промпт и лицензия шрифта — в `rust/crates/clavunora-app/assets/`.

На главной шесть крупных плиток: библиотека, обучение, свободная игра, достижения, прогресс и настройки. Верхняя строка разделов удалена; сверху — название, логотип и переключатель темы. Из каждого раздела есть кнопка возврата. Папки сложности, избранное, свои пьесы и все произведения находятся внутри библиотеки. Поиск доступен и на странице папок. Последняя открытая пьеса сохраняется для карточки продолжения. Нижнего проигрывателя нет.

Произведения и уроки представлены карточками с реальными данными, действиями открытия и избранного. Все шесть наград показаны с реальным прогрессом. Страница истории показывает реальные сводные числа и точность последних семи попыток; иллюстративные минуты занятий из макета не подставляются. В свободной игре и занятии экранная клавиатура рисует белые и чёрные клавиши с верным наложением, подсвечивает ввод, поддерживает перетаскивание мыши и отпускание за пределами клавиатуры. Внешний MIDI-диапазон прежний, экранный/компьютерный — C4–C5.

Светлая и тёмная темы сохраняются. На небольших окнах плитки перестраиваются, длинные страницы прокручиваются. Запись и экспорт остаются отложенными. Это всё ещё неполный перенос Python-приложения: оформление не добавляет редактор, импорт, фильтры рук или умные повторы.

Пакет: `dist/Clavunora-Rust-0.4.0-linux-x86_64.tar.gz`. Выпуска на GitHub в этой итерации нет.

Проверки Summer Aero: 46 Rust-тестов, в том числе нажатия всех шести главных плиток, возврат, смена темы, приоритет чёрных клавиш и отпускание мыши за пределами клавиатуры. Строгий Clippy, 170 сценариев сравнения оценки с Python и проверка совместимости библиотеки. Проверены реальные окна разделов и обе темы, архив — после распаковки на временных данных.

## Клавиатура и масштаб (0.4.1)

Настройки → «Клавиатура на экране»: 13, 25, 32, 37, 49, 61, 76 или 88 клавиш (белые и чёрные вместе), начальная MIDI-нота и масштаб 25–100%. Для 88 клавиш стандартный диапазон A0–C8. «Вписать» возвращает масштаб 100%. Настройки сохраняются в Rust-профиле; повреждённые/неподдерживаемые значения заменяются безопасными значениями по умолчанию.

Масштаб также доступен в занятии и свободной игре. Уменьшаются ширина и высота клавиш, а в падающих нотах показывается больший промежуток времени. Геометрия нот соответствует выбранному диапазону и масштабу клавиатуры. Если часть нот пьесы скрыта диапазоном, выводится предупреждение. Уменьшение масштаба не добавляет клавиши вне выбранного количества: для более широкого диапазона нужно выбрать больше клавиш.

При прослушивании клавиши подсвечиваются и падающие ноты движутся по позиции демонстрации. Подсветка не поступает в оценку. Настройки вида не меняют MIDI-ноты, темп, допуски или условия достижения; изменение масштаба не останавливает занятие. Компьютерный ввод по-прежнему C4–C5; внешнее MIDI принимается в полном диапазоне. Это отображение клавиатуры, не адаптация учебных пьес под компактный физический контроллер.

Проверки 0.4.1: 49 Rust-тестов, строгий Clippy, межъязыковая проверка библиотеки. Настоящие окна проверены на отдельном профиле: 49 клавиш C2–C6, масштаб 50%. Архив проверен по SHA-256.

## Исправление текста библиотеки (0.4.2)

Область обрезки текста карточки теперь пересекается с видимой областью прокрутки. Раньше собственный прямоугольник текста заменял область прокрутки, и заголовки частично скрытых карточек рисовались поверх соседних элементов и за пределами списка. Кнопки ограничены областью действий карточки. Длинные названия, композиторы и метаданные сокращаются по ширине; полный заголовок и композитор доступны при наведении.

Регрессионная проверка воспроизвела выход текста за пределы библиотеки до исправления и проходит после него на окнах 1200×800 и 760×540. Для снимка списка произведений доступна диагностическая страница `--capture-page library-songs` вместе с `--capture`.

## Совместимость Linux · glibc (30 октября 2026)

Ранняя локальная сборка 0.4.2 на Fedora 44 требовала `GLIBC_2.43` для `atan2f` и `acosf` из libm. Это мешало запуску на системе с glibc 2.41. Требование возникло на этапе линковки с библиотеками разработческого компьютера; обновление системной glibc на компьютере получателя не является способом установки приложения.

Переносимая сборка выполняется `scripts/build_rust_linux_compat.sh` в контейнере Debian 12 (glibc 2.36). Код монтируется только для чтения, результаты находятся в `build/rust-compat`, сеть при компиляции выключена, используются уже загруженные Rust-зависимости. Компилятор берётся из локального `build/rust-toolchain`, системные библиотеки компьютера не заменяются. В контейнере выполняются тесты, Clippy, сборка и запуск настоящего окна в Xvfb с программным OpenGL.

`scripts/check_linux_abi.py` читает версионные требования ELF через readelf и запрещает упаковку с glibc выше 2.36. Фактические требования сохраняются в `linux-compatibility.json` внутри архива. Упаковка вынесена в `scripts/package_rust_linux.sh`; обычный `build_rust_linux.sh` теперь направляет сборку в тот же совместимый контейнер.

Архив для передачи: `dist/Clavunora-Rust-0.4.2-linux-x86_64-glibc2.36.tar.gz`. Старое имя без суффикса обновляется тем же содержимым. Личные данные в архив не включаются. Драйверы графики, ALSA и необязательный FluidSynth используются из системы получателя; универсальная совместимость со всеми дистрибутивами не заявляется.

Результат проверки совместимой сборки: 50 тестов и Clippy пройдены в Debian 12; настоящий X11/OpenGL-экран сохранён через Xvfb. ELF требует максимум GLIBC_2.35; среда проверки — glibc 2.36. Архив распакован и проверен самопроверкой, обе ссылки на архив содержат одинаковый совместимый файл. Дополнительно проверено настоящее окно на Fedora 44. Ошибка сохранения также прекращает автоматические повторы до ручного продолжения. Умный повтор повышает скорость после заданного числа успешных проходов подряд, с выбранным шагом и пределом. Эффективная точность учитывает ошибки ритма/удержания, как в Python. Неудачный/прерванный проход сбрасывает серию; продолжение с середины фрагмента не повышает скорость. Скорость выше заданной цели принудительно не снижается.

В отчёт записываются исходная версия партитуры, выбранная рука, дорожки (при фильтре), границы, исходная скорость попытки и признак повторения. Фрагмент, фильтр руки/дорожек и цикл не становятся полной пьесой и не открывают награды за полное исполнение. Содержимое исходных нот и их хеш не заменяются отфильтрованным вариантом.

Прослушивание и падающие ноты используют тот же выбранный отрезок и партию. Подсказки пальцев показываются по реальной разметке нот; неизвестная аппликатура не придумывается. Их видимость сохраняется. Сопровождение второй рукой, редактор разметки, импорт, запись и экспорт в этой итерации не добавлены.

## Мягкое ожидание и обычная тема · 0.5.1

Выбор режима теперь явно показывает «С ожиданием» и «Ритм — без остановок». В ритме ошибки времени и удержания отмечаются в результате, но не останавливают музыку.

## Потеря и восстановление MIDI · 0.7.1

Список портов проверяется фоновым потоком раз в секунду после открытия настроек MIDI, без опроса ALSA при каждом кадре. Ручной выбор привязан к адресу и имени порта, а не к позиции списка. Изменение порядка портов сохраняет выбранный доступный порт. Перед открытием соединения адрес и имя проверяются повторно.

При исчезновении подключённого порта или ошибке проверки MIDI соединение закрывается, старая очередь событий отбрасывается, отпускаются только ноты и Sustain источника MIDI. Занятие останавливается; непустая попытка сохраняется как незавершённая. Экранный и компьютерный ввод остаются доступны. Музыкальная позиция сохраняется, а повтор не перезапускает музыку автоматически.

Порт для восстановления определяется по полному имени клиента и порта без изменяемого суффикса адреса ALSA. Единственное совпадение открывается заново, ошибка открытия повторяется при следующем опросе. Несколько совпадений требуют ручного выбора; первый попавшийся порт не подключается. Это сопоставление имён, а не серийных номеров оборудования. Выбор действует только в текущем запуске. Ручное «Отключить» отменяет ожидание и повторные подключения. После восстановления требуется «Начать / продолжить».

## Резервные копии · 0.8.0

В начале настроек доступны создание файла `.clavunora-backup` и выбор копии для восстановления, через системный диалог KDE/Zenity либо полный путь вручную. Перед операцией завершается занятие, сохраняются ожидающие результаты; неудачное сохранение блокирует создание/восстановление. Длительная работа выполняется отдельно от интерфейса; окно показывает ожидание и не закрывается посреди операции. Существующие файлы копий не перезаписываются.

Копия — самостоятельный согласованный снимок SQLite, а не ZIP. Он включает все четыре таблицы: пьесы (включая руки/пальцы, источники, избранное и идентификаторы импорта), попытки, настройки/достижения и ранее перенесённые записи. Создание использует SQLite Online Backup API, в том числе при открытой WAL-базе, затем целостность и записи проверяются. Новый файл сначала готовится рядом с местом назначения, синхронизируется и публикуется без перезаписи. Размер ограничен 512 МиБ.

Выбранная копия сначала переносится во временный приватный файл и проверяется: сигнатура, завершённый одиночный SQLite-файл, маркер формата, версия схемы, quick_check, точная допустимая структура таблиц без дополнительных объектов, лимиты записей, JSON нот/результатов/настроек и даты. Предпросмотр показывает количество пьес, результатов, настроек и записей. Отмена не заменяет данные. Изменение исходного выбранного файла после предпросмотра не меняет содержимое предстоящего восстановления.

Кнопка «Заменить данные этой копией» выполняет полную замену без объединения. В одной транзакции сначала фиксируется снимок текущей базы, из него создаётся страховочный файл `backups/before-restore-….clavunora-backup` в профиле. Только после успешной записи страховочного файла заменяются строки четырёх таблиц; SQL и схема из файла не исполняются. Изменение базы другим процессом после фиксации снимка приводит к отказу перехода на запись (BUSY/BUSY_SNAPSHOT); новые данные не затираются. Ошибка записи откатывает замену. Страховочный файл остаётся доступен для обратного восстановления.

После успеха окно перечитывает библиотеку и настройки. MIDI отключается, занятие не возобновляется автоматически. Python-профиль не затрагивается; старые Python ZIP-архивы в этом разделе не принимаются. Новые запись исполнения и экспорт не добавлены.

Архив: `dist/Clavunora-Rust-0.8.0-linux-x86_64-glibc2.36.tar.gz`.

Проверки 0.8.0: 80 Rust-тестов и строгий Clippy в Debian 12. Новые сценарии проверяют снимок открытой WAL-базы, сохранение четырёх таблиц, возможность отменить восстановление страховочной копией, защиту от перезаписи файла, неизменность выбранного содержимого после предпросмотра, повреждение/неподдерживаемую схему/невалидные ноты/новую версию, недоступную папку страховочных копий, занятый файл и параллельную запись после фиксации снимка. ## Метроном и сопровождение · 0.11.0

В подготовке занятия под пианино: «Настройки и разучивание» → «Метроном и сопровождение». Включение метронома использует темп исходной пьесы, tempo_map, размер (щелчки по знаменателю, акцент по числителю), скорость и позицию занятия. Отрицательное время подготовки продолжает сетку до начала пьесы. Изменения темпа не сбрасывают накопленную фазу долей. Свободный метроном остаётся в настройках/свободной игре; на паузе занятия он не включается вместо синхронного.

Для сопровождения сначала выберите руку или часть дорожек и нажмите «Применить». При выбранной руке озвучивается противоположная размеченная рука независимо от фильтра дорожек; без выбора руки озвучиваются невыбранные дорожки. Неразмеченные руки не угадываются. При выборе всей партии сопровождение недоступно. Ноты сопровождения обрезаются границами фрагмента, включая уже звучащую в его начале ноту. Отдельная громкость сохраняется вместе с переключателями.

Автоматические ноты не подаются в MIDI/PianoState/Session, не нажимают клавиши за ученика и не дают попаданий, наград или статуса полной пьесы. Встроенный синтезатор имеет отдельные голоса для ученика и сопровождения; SoundFont использует отдельный MIDI-канал. Ноты, даже одинаковой высоты, не выключают источник ученика при окончании сопровождения.

Планирование выполняется в звуковом потоке блоками по 32 кадра (менее 0,7 мс при 48 кГц, без учёта задержки ALSA/устройства). Нотные события и перекрытия подготовлены заранее; курсор не выделяет память на событиях. В ожидании звуковой поток сам ограничен ближайшей ожидаемой группой даже при задержке интерфейса. Продолжение следует за музыкальными часами; пауза, выход, потеря фокуса/MIDI и завершение снимают сопровождение и метроном. Каждый повтор получает новый номер прохода, поэтому атаки нот восстанавливаются. Задержка физического аудиоустройства и субъективный баланс требуют проверки пользователем.

Проверки: сетка размера и карты темпа, отрицательное время, дубли темпа, неизменность фазы при скорости 50%, реальный PCM нескольких секунд без обновления UI, клики без догоняющей очереди, границы фрагмента, перекрытия одинаковых нот, повторная атака, отдельные голоса, ожидание/продолжение/пауза, повтор в ритме, отключение MIDI и сохранение настроек. Общий набор из 100 тестов прошёл в Debian 12; после уточнения затухания дополнительно прошли все восемь аудиотестов, включая новый тест плавного отпускания. Проверены Clippy, готовый архив и ограничение glibc 2.36.


## Учебный нотный лист и прослушивание · 0.12.0

В подготовке под пианино выбираются три вида: «Падающие ноты», «Нотный лист», «Оба». Язык названий переключается между «До Ре Ми» и «C D E» и применяется к листу, клавиатуре и текущим подсказкам. Исходные ноты, разметка и результаты не меняются. Оба параметра сохраняются в профиле (rust:notation).

Лист рисует скрипичный и басовый станы, добавочные линейки, явные знаки альтерации, учебные длительности, аппликатуру и курсор. Сетка тактов учитывает размер и tempo_map. Руки берутся из разметки; для неразмеченных нот стан выбирается по высоте. До начала можно листать страницы тактов; начало занятия или прослушивания включает следование за музыкальной позицией. Лист показывает выбранную учебную партию, а при прослушивании всей пьесы — исходную пьесу целиком. Компоновка ограничена областью нотного листа, включая крайние MIDI-высоты; подписи плотных аккордов доступны также по наведению и строкой текущих нот.

Это учебный лист из доступных MIDI-высот и времени, а не восстановление оригинальной партитуры. В модели отсутствуют исходные тональности, паузы, нотные голоса и написание энгармонических звуков. Чёрные клавиши подписаны через диезы в обоих языках; у натуральных нот явный бекар. Значки длительности округляются к ближайшему учебному значению по карте темпа, тонкая линия сохраняет фактическую длину. Продолжение ноты через границу страницы отмечается без повторного штиля. Полная издательская вёрстка и PDF-экспорт не добавлялись.

Над пианино доступны «Послушать всю пьесу» и, при выбранной партии/фрагменте, «Послушать выбранную партию». Повторное нажатие останавливает прослушивание. Вся пьеса играет от начала независимо от учебного фильтра; выбранная партия — в применённых границах и дорожках. Скорость берётся из подготовки. Звуки, включая короткие ноты и повторения, планируются в аудиопотоке, а не на кадрах UI. Громкость сопровождения не приглушает демонстрацию; общая громкость/выключение звука действуют. Прослушивание не запускает оценку, не создаёт историю и не нажимает клавиши в PianoState. Начало занятия, переход в другой раздел, изменение учебного плана и конец фрагмента останавливают его.

Проверки включают переводы названий/октавы, хроматику, страницу по карте темпа, крайние MIDI-высоты, плотный аккорд, оба языка и темы, сохранение через настоящие переключатели UI, видимость клавиатуры в маленьком окне/полноэкранных режимах, полное и выбранное прослушивание, скорость и границы, завершение и отсутствие фиктивного прогресса.
