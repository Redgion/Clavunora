# Clavunora 1.0.0-rc.1 · подготовка desktop-релиза

Текущий выпуск — кандидат для проверки, не заявление об аппаратной совместимости со всеми инструментами. Репозиторий остаётся закрытым. Workflow `rust-desktop.yml` создаёт только приватные артефакты; публикации релиза, тегов и изменения доступа нет.

## Пакеты

| Система | Пакет | Установка |
|---|---|---|
| Linux x86_64 | `Clavunora-Rust-1.0.0-rc.1-linux-x86_64-glibc2.36.tar.gz` | Распаковать и выполнить `./install.sh`; ярлык появляется в меню. Можно запускать из распакованной папки. |
| Windows x64 | `Clavunora-1.0.0-rc.1-windows-x64-setup.exe` и portable ZIP | Установка для текущего пользователя без прав администратора. В portable ZIP сохранять всю папку ресурсов рядом с EXE. |
| macOS Apple Silicon | `Clavunora-1.0.0-rc.1-macos-arm64.dmg` и ZIP | Перетащить `.app` в Applications. |
| macOS Intel | `Clavunora-1.0.0-rc.1-macos-x86_64.dmg` и ZIP | Отдельная нативная сборка Intel. |

Linux собирается локально в Debian 12; CI — в Ubuntu 22.04. Проверка запрещает требование glibc новее 2.36. Windows собирается на Windows с MSVC и статическим CRT; отдельная установка Visual C++ Redistributable не должна требоваться (импорты EXE проверяются упаковщиком). Цели проверки — Windows 10/11 x64 и macOS 11+; минимальная версия macOS зафиксирована в сборке/Info.plist, но проверка на старейшей ОС требует настоящего устройства. Нативная успешная сборка на современной ОС не подтверждает весь заявленный диапазон.

Общий Rust-код, оценка и форматы профиля одинаковы. Linux использует ALSA, Windows — WASAPI, macOS — CoreAudio через CPAL; MIDI — midir с системным backend. Системные диалоги Windows/macOS работают через rfd; Linux использует kdialog/zenity с возможностью вручную указать путь. Все платформы имеют встроенный инструмент; необязательный SoundFont требует отдельно установленного FluidSynth и аппаратной проверки.

## Профиль и обновление

- Linux: `$XDG_CONFIG_HOME/Clavunora` либо `~/.config/Clavunora`.
- Windows: `%APPDATA%\Clavunora`.
- macOS: `~/Library/Application Support/Clavunora`.
- Если нового профиля ещё нет, а `ClavunoraRustPreview/library.sqlite3` уже существует в том же корне, приложение продолжает использовать его на месте. Копирования и объединения баз нет.
- Профиль Python `PianoFlow` не выбирается автоматически. Явный импорт создаёт отдельную копию.
- Установщики не содержат пользовательские базы и не удаляют прогресс при деинсталляции. Linux хранит версии программы отдельно и атомарно переключает `current`; предыдущий каталог остаётся доступным до удаления приложения.

Перед массовым тестированием сохраните копию через настройки. Формат SQLite и сохранённые результаты остаются совместимыми; отказ от импорта старых записей исполнения не означает их удаления.

## Проверки сборки

CI строит исходники и четыре native-варианта на одном коммите, выполняет Rust-тесты, fmt и строгий Clippy. Каждый упакованный бинарник запускает `--self-test` вне каталога исходников: 124 записи библиотеки, временный профиль, проверка ресурсов и логики. Windows дополнительно проверяет установку, повторную установку и удаление с сохранением профиля; macOS — системные dylib и ad-hoc подпись пакета; Linux — ABI и настоящее окно через Xvfb. Автоматические тесты не заменяют слуховую оценку и физический MIDI.

Нативные задания: `ubuntu-22.04`, `windows-2025`, `macos-15` (Apple Silicon), `macos-15-intel`. Названия проверены по официальному [списку образов GitHub](https://github.com/actions/runner-images). При выполнении вне CI используется зафиксированный Rust 1.99.1; CARGO.lock фиксирует зависимости. Метаданные пакетов и SHA-256 сохраняются рядом с файлами.

Команды локальной подготовки:

```sh
./scripts/build_rust_linux.sh
# Windows/macOS, после native cargo test/clippy/build:
python scripts/package_rust_desktop.py --binary PATH_TO_NATIVE_BINARY --source dist/Clavunora-Rust-1.0.0-rc.1-source.tar.gz
```

Windows EXE собирается с `RUSTFLAGS="-C target-feature=+crt-static"`. В macOS задаётся `MACOSX_DEPLOYMENT_TARGET=11.0`. Windows-установщик собирается Inno Setup 6: `scripts/check_windows_installer.ps1`. Linux-архив содержит пользовательские install/uninstall-скрипты; он не является DEB/RPM/AppImage.

## Подпись

Кандидат Windows пока без подписи издателя. Mac-пакеты подписаны ad-hoc для проверки целостности, без Developer ID и нотариального подтверждения. Это не готовая доверенная подпись для публичной загрузки; предупреждения системной защиты возможны.

Для публичного выпуска с подписью владелец предоставляет собственные средства подписи вне репозитория:

- Windows: сертификат в хранилище Windows и SignTool; `scripts/sign_windows_release.ps1`. Подписать EXE перед упаковкой, затем итоговый установщик; пересоздать контрольные суммы.
- macOS: Developer ID Application и профиль notarytool в Keychain; `scripts/sign_macos_release.sh`. Подписать с hardened runtime, дождаться notarization, добавить ticket и проверить результат. После этого пересоздать ZIP/DMG и контрольные суммы из подписанного `.app`.

Ключи и пароли не сохраняются в исходниках и не загружаются автоматически. Скрипты подписи не выполняются обычным CI. Ни приобретение сертификатов, ни оформление аккаунтов, ни отправка на публикацию этим этапом не выполняются.

## Исходники и лицензии

Перед упаковкой автоматически проверяются исходники и содержимое бинарных пакетов: локальные пути домашних папок, распространённые форматы ключей/токенов и файлы профиля блокируют сборку. В диагностических строках Rust пути машины сборки заменяются на `~` и `~/Clavunora`. Обнаруженные секреты не выводятся в отчёт — только относительный файл и категория. Такая проверка не гарантирует распознавание любых личных данных; перед публичной публикацией нужен отдельный просмотр содержимого и Git-истории. История приватного репозитория в архив исходников не включается. Обязательные имена авторов, контакты и уведомления сторонних лицензий сохраняются.

Рядом с бинарниками передаётся `Clavunora-Rust-1.0.0-rc.1-source.tar.gz` со всеми файлами проекта, Cargo.lock, vendored-зависимостями и инструкцией сборки. SOURCE_FILES.json фиксирует снимок; SOURCE.txt в пакете указывает имя и SHA-256 соответствующего архива. Общедоступный GitHub не обязателен для внутреннего тестирования; каждый получатель бинарника должен иметь соответствующий доступ к исходникам.

GPL-3.0-only относится к оригинальному коду. Музыка, шрифты и зависимости сохраняют собственные условия; две неподтверждённые редакции по-прежнему исключены. Наличие в каталоге NC-редакции не позволяет называть весь набор ресурсов свободным для коммерческого использования.
